1. **生效的是统一登录页 `www.lawyers.org.cn/openid/login.jsp`**，不是 OA 登录页
   —— OA 的会话**不覆盖** `recruitment` 子域。`ensure_login()` 顺序：复用登录态 → openid → OA。
2. 登录页的 `console.log("不是ie的浏览器")` 只是死分支，**站点不要求 IE**；
   `static.homolo.net` 字体加载失败只影响图标。
3. 未登录访问管理页是**导航被中断（`ERR_ABORTED`）**，不是跳转登录页 → `goto` 需容错。
4. ExtJS 的 `<div id="loading">` 遮罩会拦截点击 → 先等遮罩消失，再退化成 JS 点击绕过。
5. 置顶规则比预想严格：确认弹窗原文为「20 天之内只有使用一次置顶的机会」
   ⇒ 一个周期只点一次，**失败也绝不重试**。

**实测结果**：删除登录态文件后仍能自动登录，随后 `days_since=4`、`row_selected=true`、弹窗正确捕获并取消。

### 登录态复用率（已确认属站点特性，非缺陷）

云端每次运行后登录态都会正确写回 OSS，但下次运行仍是 `auth_reused=false`。
原因：招聘后台的会话 Cookie `JSESSIONID` 是 `expires=-1` 的**会话级 Cookie**，
服务端 session 空闲期短，隔天必然失效。

代码已自动降级为「账号密码重新登录」（`publisher.ensure_login()`），功能不受影响，
只是每天多一次接触登录页的机会。`auth_reused` 长期为 false 属正常；
但**若连自动登录都失败**，2026-10-03 加的早报警机制会立即给管理员发邮件 + 短信告警。
