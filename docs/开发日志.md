## 2026-10-03（续）：验证「OA 登录路线」不可行 + 加固告警/登录态

### 验证：能否改用 OA 登录规避 passport3 变更？—— 结论：不能

写了 `tools/verify_oa_sso.py`，两段都证明**招聘后台与 OA 是独立认证域，无共享 SSO**：

- **A 段（复用真人已登录的 OA 会话）**：拷贝 Edge 用户目录（带真人 OA cookie），
  确认 `OA 登录态 = logged_in`，但访问 `recruitment.lawyers.org.cn/manager/index.jsp`
  **仍被踢到 `passport3.lawyers.org.cn/login.jsp`**；OA 大厅也没有指向招聘后台的 SSO 入口。
- **B 段（脚本程序化登 OA）**：成功登进 OA（`/workbench/`），访招聘后台同样被踢回 passport3。

含义：你平时能进招聘后台，是因为浏览器**单独**登了 passport3（与 OA 是两次独立登录）。
所以「改用 OA 登录」并不能规避 passport3 变更——机器人该登的还得登 passport3。
**维持 passport3 路线 + 做好登录态复用与失败告警**，不要走 OA 路线。

### 开工：复用登录态 + 失败告警

- 登录态复用（`storage_state`）其实早已接通：`run()` 用 `store.load_auth()` 播种上下文，
  `finally` 里 `on_auth()` 回写。本次新增：
  - `result["auth_reused"]` 字段，明确本轮是「复用」还是「重新登录」；
  - 若**带了登录态却失效**（被迫重登），打 warning：「频繁出现可能意味着 passport3 改版」——
    这正是用户要的早报警信号；
  - `on_auth` 回写失败时打 warning（否则下次被迫重登，增加接触登录页的频次）。
- 失败告警补全：
  - `notifier.notify_exception()` 之前**只定义没接**；本次在 `main()` / `handler()` 顶层
    包 try/except，任何崩溃（OSS 不可用、逻辑异常）都给管理员发 邮件 + 短信；

### 踩坑记录（按顺序，每条都卡住过）

1. **FC OpenAPI 接入点格式**：`<region>.fc.aliyuncs.com` → DNS 解析失败；
   `fc.<region>.aliyuncs.com` → 报 `InvalidVersion`。
   **官方格式是 `<主账号ID>.<region>.fc.aliyuncs.com`**（账号 ID 在最前）。
   现在不再手填账号 ID，改用 STS `GetCallerIdentity` 动态取，少维护一个 Secret。
2. **`:latest` 被 FC 按 digest 缓存**：update 返回成功、函数名也打印了，但函数仍在跑旧镜像
   ——表现为「明明修好了 playwright，却一直报未安装」。改用 sha 标签后立刻生效。
3. **装和跑不是同一个 python**：基础镜像自带 playwright，但裸 `pip install` 可能装进别的解释器。
   改成 `python -m pip install` 与 CMD 同一个 interpreter，并加构建期自检，
   让问题在 CI 阶段就暴露而不是拖到 FC 运行时。
4. **SLS 默认不开启**：函数 → 日志 → 「一键启用」，且启用前的日志补不回来。
5. **FC 环境变量漏 `OA_USER`/`OA_PASS`**：登录态失效后无法重登 → 直接失败。

### 关于 `auth_reused=false`（已定位，属站点特性）

登录态确实正确写回 OSS（`auth/firm_a.json` 每次运行后都更新），但下次运行仍显示重新登录。
看保存的 JSON 即知原因：招聘后台的 `JSESSIONID` 是 `expires: -1` 的**会话级 Cookie**，
服务端 session 空闲期短，隔天必然失效。

代码自动降级为账号密码重登（`publisher.ensure_login()`），功能不受影响；
`auth_reused` 长期 false 属正常，**但自动登录若也失败会立即触发管理员邮件 + 短信告警**。
