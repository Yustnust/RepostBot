## 一、页面入口链路（已实测打通）

```
1. https://oa.lawyers.org.cn/hall/                       OA 大厅（登录态起点）
      └─ 菜单里有「事务所招聘」链接
2. https://www.lawyers.org.cn/member/talentexchange      人才交流页
      └─ 页面上有「点击此处发布招聘」
         href=/openid/login.jsp?loginSuccessUrl=https://recruitment.lawyers.org.cn/manager/index.jsp
3. https://recruitment.lawyers.org.cn/manager/index.jsp  ★ 招聘管理后台（真正操作页）
```

> 注意：是 `manager`（不是 `manage`）。直接访问未登录时返回 404，需先有登录态。
> 自动化时可直接 `page.goto(RECRUIT_MANAGER_URL)`，已登录会直接进入。

## 二、技术栈（决定选择器写法）

- 前端框架：**Ext JS 2.x**（`x-grid3-row` / `x-btn` / `x-toolbar`）
- ⚠ ExtJS 的按钮 id 是**动态生成**的（`ext-gen18`~`ext-gen34`），每次加载都可能变。
  **一律用文本定位**（`button:has-text("更新排序时间")`），禁止写死 id。
- ⚠ 页面存在已知 JS 报错：`dialog.js:32 Uncaught TypeError: $.widget is not a function`
  （jQuery UI 未加载成功）。「更新排序时间」用的是**浏览器原生 `confirm()`**，不受影响。
- 页面含一个 7moor 在线客服 iframe（无关，忽略）。

## 二点五、登录（2026-09-28 勘察确认；2026-10-03 入口巡检校正）

> ⚠ **站点有两套并存的登录体系，别混为一谈**（2026-10-03 用 `diag_login.py --entries` 实测）：
>
> | 入口 | 最终停在 | 字段 | 对招聘后台是否有效 |
> |---|---|---|---|
> | `oa.lawyers.org.cn/login.jsp`（**OA，用户日常手工登录的就是它**） | 本页，**未改造** | `j_username` / `j_password` | ❌ 会话不覆盖 recruitment 子域 |
> | `www.lawyers.org.cn/openid/login.jsp` | **302 → passport3** | — | ✅ 脚本首选 |
> | `recruitment.lawyers.org.cn/manager/index.jsp` | **302 → passport3** | — | ✅ |
> | `passport3.lawyers.org.cn/login.jsp`（「律师一卡通」） | 本页 | `username` / `password` + 「立即登录」 | ✅ 已验证 |
>
> 即：**OA 页面没变，变的是招聘系统这条链路**（openid → passport3）。
> `#j_username` 对 OA 页面依然有效，只是对招聘后台无用。详见 §6.1。

登录页：`https://oa.lawyers.org.cn/login.jsp`（Spring Security 表单）

```html
<input type="text"     name="j_username" id="j_username" placeholder="请输入用户名">
<input type="password" name="j_password" id="j_password" placeholder="密码">
<button class="btn btn-success btn-block">登录</button>
```

选择器：`#j_username` / `#j_password` / `button.btn.btn-success.btn-block`

> 已写入 `src/page_selectors.py` 的 `LOGIN_USERNAME / LOGIN_PASSWORD / LOGIN_SUBMIT`。

**实测结论（重要）**：

1. 页面里那句 `console.log("不是ie的浏览器")` 只是浏览器判断的死分支，**站点并不要求 IE**，可忽略。
2. **OA 登录页的会话不覆盖 `recruitment` 子域**。自动登录生效的是**统一登录页**：
   `https://www.lawyers.org.cn/openid/login.jsp`（招聘后台本来就是经它做 SSO）。
   因此 `publisher.ensure_login()` 优先尝试 openid 登录页，OA 登录页作为备选。
3. 登录页加载较慢（部分静态资源 `static.homolo.net` 被墙），**必须先等 `#j_username` 出现再填表**。
4. 未登录时直接访问 `manager/index.jsp` 不是跳登录页，而是**导航被中断（ERR_ABORTED）**，
   所以代码里对 `goto` 做了容错，不能直接抛异常。

## 三、★ 核心确认：置顶按钮

- 按钮文本：**「更新排序时间」**
- 选择器：`button:has-text("更新排序时间")`
- **无需先选中行**即可点击（同组「修改/删除/发布招聘/结束招聘」未选行时均为 `x-item-disabled`，
  而「更新排序时间」始终可用）
- 点击后弹**浏览器原生 confirm**，原文：

```
更新排序时间的操作在20天之内只有使用一次置顶的机会，请确认是否使用？
```

> ⚠ 实现要点：
> 1. 这是**原生 `confirm()`**，Playwright 默认静默取消 → 必须注册 `page.on("dialog")`
> 2. **每 20 天周期只有 1 次机会，点了就消耗** → 必须确认满 20 天才点，且只点一次
> 3. dry-run 模式下绝不能调用 `dialog.accept()`

## 五、目标行的判定逻辑（阶段2 实现依据）

```
在招聘管理列表第 1 页中：
  找到 状态(列9) == "招聘中" 的行
  读取该行 排序时间(列6)
  若 (今天 - 排序时间).days >= 20  →  点击「更新排序时间」
```

若存在多条「招聘中」，取排序时间最早（最该置顶）的一条；若无「招聘中」行，跳过。

## 六、★ 接口层（2026-10-03 实测：站点已换登录体系，且拿到了置顶接口）

> 这一节是用 `python tools/probe_api.py` + `--trace` 抓出来的，是把部署从
> **1.5GB 的 Playwright 镜像**精简成**几 MB 的 HTTP 直调**的关键依据。

### 6.1 登录（招聘这条链路已改，OA 那条没改）

```
POST https://passport3.lawyers.org.cn/j_spring_security_check
表单：j_username=<账号>
     j_password=<前端加密后的密文，肉眼不可读，内含 ":::" 分隔>
     _spring_security_remember_me=false
     j_verificationcode=           （空）
成功后跳转：https://passport3.lawyers.org.cn/login.jsp?$=success
```

- ✅ **招聘后台的登录页现在是 `passport3.lawyers.org.cn/login.jsp`（「律师一卡通」）**：
  字段 `#username` / `#password`，按钮「立即登录」（另一个是「中国律师身份核验登录」）。
  `www.lawyers.org.cn/openid/login.jsp` 与招聘管理页都会 302 过去。
- ✅ **OA（上海市律师综合管理信息系统）没改**：`oa.lawyers.org.cn/login.jsp` 仍是
  `#j_username` / `#j_password` + 「登录」按钮。用户手工登录看到的是它，所以察觉不到变化。
  ⚠ 但 OA 的会话**不覆盖** `recruitment` 子域，用 OA 登录进不了招聘后台。
- 脚本的入口顺序（`publisher.ensure_login`）：`openid`（→passport3） → `passport3` 直连 → OA（兜底）。
- 实测小坑：无头访问时 `openid` / `oa/hall` 偶发 `net::ERR_TIMED_OUT`，
  所以整轮重试 + 多入口兜底是必要的。
- ❓ 未解决：`j_password` 的前端加密方式尚未定位。
  排查方向：用**未登录**的干净上下文打开 passport3 登录页再扫脚本
  （带着已登录 cookie 访问时页面会直接跳走，脚本抓不全）。

### 6.3 ★ 置顶（真正要调的那个方法）

页面 JS（`cn.org.lawyers.recruitment.page.MyRecruitmentManagement`）里的源码：

```js
top: function () {
  if (confirm('更新排序时间的操作在20天之内只有使用一次置顶的机会，请确认是否使用？')) {
    RecruitmentService.getInstance().updateCompanyTopSortTimes(
      '$CurrentUserCompanyId', false, function (r) {
        if (r.code == 1)            { page.refresh(); }              // 成功
        else if (r.code == -3)      { alert("对不起，您暂时不能更新排序时间！"
                                     + "（距离上一次更新排序时间‘" + new Date(r.result).format('Y-m-d')
                                     + "’至少需要超过20天！）"); }
        else                        { Ext.ux.TipBox.error('提示','关闭失败!',2); }
      });
  }
}
```

**关键结论**

1. 方法名：`updateCompanyTopSortTimes`，参数 `('$CurrentUserCompanyId', false, callback)`。
   第二个参数 `false` 的含义未知 → **必须等 10-14 真实抓包确认后再照抄**。
2. 走的是 homolo 的 JSON-RPC（`com.homolo.webapps.service.JSONRpcService`），
   端点大概率与列表同域：`/service/webdata/`。
3. **服务端自己做 20 天校验**：未到期返回 `code == -3`，并把「上次更新时间」放在 `r.result`。
   ⇒ 万一误点/重复点，服务端会拒绝；但这不代表可以不校验，仍按 20 天 + 保护窗口执行。
4. 因此「一个周期只能一次」是**前端 confirm + 后端 -3 双重校验**。

同类的其他方法（供将来扩展，勿误调）：
`deleteRecruitment / openRecruitment / closeRecruitment / syncCompanyInfo`。
