### 为什么容器入口是 `bootstrap.py` 而不是 `index.py`

FC 的**事件函数 + 自定义容器镜像**要求容器内跑一个监听 **9000 端口**的 HTTP 服务，
定时触发器的调用由平台以 HTTP 转发进来（`GET` 为就绪探测、`POST` 为真实调用）。

`src/index.py` 的 `main()` 是命令行入口（跑完就退出、不监听任何端口），直接拿来做容器 CMD
会让容器起来即退出、FC 报 `CAExited`。故新增 `src/bootstrap.py` 做转接层：

- `GET` → 直接回 200（平台就绪探测）
- `POST` → 调用 `index.handler(event, context)`，结果以 JSON 返回

本机 CLI 仍用 `python src/index.py`，不受影响。

## 二、定时触发器（重要）

```
CRON_TZ=Asia/Shanghai 0 0 9 * * * *
```

- **必须加 `CRON_TZ=Asia/Shanghai`**，FC 的 Cron 默认按 UTC，不加会差 8 小时（变成 17:00）。
- 字段顺序：`秒 分 时 日 月 周 年`。若控制台不接受 7 位，改 6 位 `0 0 9 * * *`。
- **创建后务必用控制台的「下次触发时间」预览核对**，确认为北京时间 09:00。
- 为什么是每天：**只检查，不动作**。程序读到「排序时间」后自己算天数，满 20 天当天才真正点击。每天检查约 15 秒，成本可忽略，且天然自愈（今天失败明天自动补）。

> 不要用 `*/20`：它表示每月 1 日和 21 日，周期会退化成 30 天。
> 也不要用 EventBridge 的 Rate 表达式：周期起点固定，无法跟随实际置顶时间，且失败后要空等 20 天。

| 变量 | 说明 |

| `TZ` | `Asia/Shanghai` |

| `OSS_KEY_PREFIX` | 如 `repostbot/` |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` / `..._SECRET` | OSS 用（**个人账号**）。若 FC 已绑个人账号 RAM 角色，运行时会自动注入，可留空；仅本机调试 / 无角色时填 |
| `SMS_ACCESS_KEY_ID` / `..._SECRET` | 短信用（**企业账号**，短信须企业实名）。**必须显式填写**：FC 的 RAM 角色在个人账号，无法跨账号访问企业短信，故短信不能走角色注入，只能填企业账号 AK |

| `SMTP_FROM` | 可选。发件人完整地址；不填时由 `SMTP_USER` + 域名推导（163 邮箱要求 From 必须是完整地址且与登录账号一致，否则 `550 Invalid User`） |
| `NOTIFY_CLIENT_ON_FAILURE` | 默认 `false`：失败只通知管理员，不打扰客户 |
| `NOTIFY_EMAIL` | 客户收件邮箱（缺省回执地址） |
| `ADMIN_EMAIL` | 失败告警收件人 |
| `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE` | 短信签名与模板（审核通过后填入） |
| `NOTIFY_PHONE` | 客户手机号；并把 `accounts.json` 中该账号的 `sms_enabled` 设为 `true` |
| `OA_USER` / `OA_PASS` | ⚠️ **必填**。登录态失效时用于自动重新登录；缺失会直接跑失败（见 §五） |
| `ADMIN_PHONE` | 管理员手机号，收失败告警短信（配合 `SMS_TEMPLATE_CODE_ALERT` 生效） |

### 短信：控制台只办手续，发送走 API

控制台的「发送短信」是手动群发，**机器人用不了**。实际发送由程序调用短信 API 完成。

模板内容必须包含我们代码传入的两个变量（`time` / `nexttime`）：

**模板一：客户成功回执**（`SMS_TEMPLATE_CODE`）

```
您的招聘信息已于${time}在东方律师网完成置顶更新，下次可更新时间为${nexttime}
```

**模板二：管理员失败告警**（`SMS_TEMPLATE_CODE_ALERT`）

```
${name}的招聘置顶未成功，原因：${reason}，请及时登录处理（${time}）
```

> 变量名必须与代码一致（`notifier/sms.py` 里 `params` 的 key），否则发送失败。
> 模板类型选**通知类**；变量值会自动截断（律所名 12 字、原因 20 字）。
> 失败时管理员**同时收邮件和短信**（邮件可能没人及时看，短信保证第一时间触达）。
| `<FIRM>_OA_USER` / `<FIRM>_OA_PASS` | 各律所 OA 凭据，对应 `accounts.json` 里的 `env:` 引用 |

> 邮件在 FC 里**必须**用 `SMTP_SSL(host, 465)`；用 25 端口会报 `[Errno 101] Network is unreachable`。

### 凭证：OSS 走 RAM 角色，短信走独立 AK（双账号拆分）

部署架构：**OSS / ACR / FC 在个人账号，短信在（企业实名）企业账号**，二者是不同主账号，凭证必须分开。

| 资源 | 凭证方式 | 说明 |
|---|---|---|
| OSS（个人账号） | **FC RAM 角色**（推荐） | 给函数绑个人账号角色并授 OSS 读写，运行时自动注入 `ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET/SECURITY_TOKEN`，无需静态 AK |
| 短信（企业账号） | **`SMS_ACCESS_KEY_*` 环境变量** | 个人账号 RAM 角色**无法跨账号**访问企业 Dysms，短信必须显式填企业账号 AK；`notifier/sms.py` 优先读 `SMS_ACCESS_KEY_*`，落空才回退 `ALIBABA_CLOUD_ACCESS_KEY_*` |
| 本机调试 | **长期 AccessKey** | `.env` 同时填个人账号 AK（OSS）+ 企业账号 AK（`SMS_ACCESS_KEY_*`） |
| GitHub Actions | **长期 AccessKey（个人账号）** | `ALIYUN_ACCESS_KEY_*`（GitHub Secrets，仅推 ACR + 更新 FC），与短信无关 |

代码已自动识别两类凭证（检测到 `ALIBABA_CLOUD_SECURITY_TOKEN` 就走 STS）：

- `storage.py` → `oss2.StsAuth(...)`（OSS，走 RAM 角色注入的 STS）
- `notifier/sms.py` → 设了 `SMS_ACCESS_KEY_*` 用该组企业 AK（不带 token）；未设则回退 `ALIBABA_CLOUD_ACCESS_KEY_*`

> ⚠️ FC 的 RAM 角色**只能授权个人账号内的资源**（OSS 等），**不能**授予 `AliyunDysmsFullAccess`（那是企业账号权限）。短信独立 AK 是拆分部署下唯一正确做法。
> 另外只有 **GitHub Actions** 才需要长期 AK（推镜像 / 更新函数），且用个人账号 AK 即可。

## 五、登录态的处理（关键）

FC 上无人值守，登录态 Cookie 会过期。两条保障：

1. **自动登录兜底**（已实测通过）：登录态失效时，程序依次尝试
   `https://www.lawyers.org.cn/openid/login.jsp`（**生效的就是它**）与
   `https://oa.lawyers.org.cn/login.jsp`，用 `#j_username` / `#j_password` 填表提交。
   注意 OA 登录页的会话**不覆盖** recruitment 子域，所以 openid 登录页排在最前。
2. **失败即告警**：自动登录也失败时，返回失败并发管理员邮件，不会静默跳过

登录态文件仍是第一优先（更快、更不容易触发风控）。由于 OSS 已迁到**个人账号新 bucket**，
登录态的生成与上传统一由 `init_oss.py` 完成（不要再手动 cp 到旧 bucket）：

```powershell
# 1) 本机用 recon.py 生成登录态（仅首次 / 登录态失效时跑）
python tools/recon.py --firm firm_a --browser msedge
#    登录后按 q 退出，登录态写入 .auth/firm_a.json

# 2) 用 init_oss.py 把三件套（含登录态）一次性迁移/上传到个人账号新 bucket 并回读校验
python tools/init_oss.py --yes
```

`init_oss.py` 读取 `.env` 中**个人账号**的 `OSS_BUCKET` / `OSS_ENDPOINT` / AccessKey，
把 `accounts.json` / `state.json` / `auth/firm_a.json` 上传到新 bucket 并**回读校验**，
同时打印推算出的下次可置顶日期供核对。

> **从旧（企业账号）bucket 迁移**：先确认 `.env` 已改指向个人账号新 bucket，再跑
> `init_oss.py` 即可覆盖上传；回读正常后可释放旧 bucket（释放前请先确认新三件套已就绪）。

### ⚠️ 上线踩坑记录（2026-10-08，每一条都真实卡住过）

1. **FC OpenAPI 接入点必须是 `<主账号ID>.<region>.fc.aliyuncs.com`**
   （官方：`help.aliyun.com/zh/fc/developer-reference/endpoints`），**主账号 ID 拼在最前**。
   - 写成 `<region>.fc.aliyuncs.com` → DNS 解析失败（尽管本机 `nslookup` 可能因为泛解析看似能通）
   - 写成 `fc.<region>.aliyuncs.com` → 命中别的网关，报 `InvalidVersion: Specified parameter Version is not valid`
   - 现 `deploy.yml` 不再手填账号 ID：用 STS `GetCallerIdentity` 动态查出后拼接，少一个 Secret。

2. **给函数的镜像标签绝不能用 `:latest`**：FC 按 **digest** 缓存容器镜像，地址字符串不变时**不会重新拉取**
   ——「update 返回成功」≠「跑的是新镜像」。曾因此反复报「未安装 playwright」。
   `deploy.yml` 现用 `${GITHUB_SHA::8}` 更新函数，每次提交地址必变，强制拉新。

3. **容器里要用与 CMD 同一个解释器装依赖**：写 `python -m pip install`，不要用裸 `pip`。
   装和跑不是同一个 python 时，会出现「基础镜像明明自带 playwright、运行时却 import 不到」。
   `Dockerfile` 另加了构建期自检 `python -c "import playwright.sync_api, oss2"`，装不上直接构建失败，
   不把问题拖到 FC 运行时。

4. **SLS 要手动开**：函数 → 日志 → 一键启用，否则线上出问题查不到任何东西（且启用前的日志补不回来）。

5. **环境变量别漏**：`OA_USER` / `OA_PASS` 缺失时，只要登录态失效就必然失败。

> 调试手段：函数 → 测试 → 「测试函数」（事件体留空即可，`handler` 不读 event）。
> 首次调用是冷启动（拉镜像 + 起 Chromium + 登录），约 1~2 分钟属正常，不要连点。

## 七、回滚

镜像每次构建都打 `latest` 与 commit sha（前 8 位）两个标签；**给 FC 用的是 sha 标签**。
出问题在函数 → 配置 → 基本信息里把镜像地址改回上一个 sha 即可（**不要改回 `:latest`**，见上文踩坑 2）。

## 八、本机定时运行（上云前的过渡方案 / 永久备份方案）

> 用途：确保**不错过置顶窗口**。首次真实置顶日是 2026-10-14，若届时 FC 尚未配好，
> 用本机计划任务兜底，避免再等 20 天。

### 1. 运行脚本

`scripts/run_daily.ps1`：切到仓库根目录 → 调用 `src/index.py` → 输出写入 `logs/daily_<时间戳>.log`，
同时用 `--trace` 记录网络请求到 `logs/trace_<时间戳>.json`。

行为由 `.env` 的 `DRY_RUN` 决定：`true` 只检查不真点，`false` 满 20 天当天真正置顶。

### 2. 注册计划任务（每天 09:00）

以**管理员或当前用户**身份在 PowerShell 执行：

```powershell
schtasks /create /tn "RepostBot" /sc daily /st 09:00 /f /tr "powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"D:\work\娜娜\自动招聘发布\scripts\run_daily.ps1\""
```

### 3. 常用管理命令

```powershell
schtasks /query /tn "RepostBot"        # 查看状态与下次运行时间
schtasks /run   /tn "RepostBot"        # 立即跑一次（用来验证配置）
schtasks /delete /tn "RepostBot" /f    # 删除任务
```

### 4. 注意事项

- **电脑需开机且已登录**（默认只在用户登录时运行）。若需要关机也能跑，必须上云（FC）。
- 任务计划程序中 PATH 可能不完整，脚本里对 python 路径做了兜底查找。
- 验证时先手动跑一次：`powershell -File scripts\run_daily.ps1`，再 `schtasks /run` 测试。
