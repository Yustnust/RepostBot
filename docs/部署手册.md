## 二、定时触发器（重要）

```
CRON_TZ=Asia/Shanghai 0 0 9 * * * *
```

- **必须加 `CRON_TZ=Asia/Shanghai`**，FC 的 Cron 默认按 UTC，不加会差 8 小时（变成 17:00）。
- 字段顺序：`秒 分 时 日 月 周 年`。若控制台不接受 7 位，改 6 位 `0 0 9 * * *`。
- **创建后务必用控制台的「下次触发时间」预览核对**，确认为北京时间 09:00。
- 为什么是每天：**只检查，不动作**。程序读到「排序时间」后自己算天数，满 20 天当天才真正点击。每天检查约 15 秒，成本可忽略，且天然自愈（今天失败明天自动补）。

> 不要用 `*/20`：它表示每月 1 日和 21 日，周期会退化成 30 天。
> 也不要用 EventBridge 的 Rate 表达式：周期起点固定，无法跟随实际置顶时间，且失败后要空等 20 天。

## 三、环境变量（在 FC 控制台配置，敏感项勾选加密）

| 变量 | 说明 |
|---|---|
| `DRY_RUN` | 上线初期设 `true` 演练，观察 2~3 天后再改 `false` |
| `TZ` | `Asia/Shanghai` |
| `OSS_BUCKET` / `OSS_REGION` / `OSS_ENDPOINT` | OSS 配置（OSS_ENDPOINT 可用公网地址） |
| `OSS_KEY_PREFIX` | 如 `repostbot/` |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` / `..._SECRET` | 短信用（RAM 子账号，仅授 `AliyunDysmsFullAccess`） |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | 发件邮箱；**端口 465 + SMTP_SSL** |
| `SMTP_FROM` | 可选。发件人完整地址；不填时由 `SMTP_USER` + 域名推导（163 邮箱要求 From 必须是完整地址且与登录账号一致，否则 `550 Invalid User`） |
| `NOTIFY_CLIENT_ON_FAILURE` | 默认 `false`：失败只通知管理员，不打扰客户 |
| `NOTIFY_EMAIL` | 客户收件邮箱（缺省回执地址） |
| `ADMIN_EMAIL` | 失败告警收件人 |
| `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE` | 短信签名与模板（审核通过后填入） |
| `<FIRM>_OA_USER` / `<FIRM>_OA_PASS` | 各律所 OA 凭据，对应 `accounts.json` 里的 `env:` 引用 |

> 邮件在 FC 里**必须**用 `SMTP_SSL(host, 465)`；用 25 端口会报 `[Errno 101] Network is unreachable`。

### 凭证：优先用 RAM 角色，不要把 AK 放进函数

| 运行位置 | 凭证方式 |
|---|---|
| 阿里云 FC（推荐） | **RAM 角色**：给函数绑定角色后，运行时自动注入 `ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET/SECURITY_TOKEN`，凭证自动轮换，函数里**无需配任何 AK** |
| 本机 / GitHub Actions | **长期 AccessKey**：填在 `.env` 或 GitHub Secrets |

代码已自动识别两种方式（检测到 `ALIBABA_CLOUD_SECURITY_TOKEN` 就走 STS）：

- `storage.py` → `oss2.StsAuth(...)`
- `notifier/sms.py` → `cfg.security_token = ...`

FC 的 RAM 角色需授权：**OSS 读写（仅本 bucket）** + **`AliyunDysmsFullAccess`**（短信）。
只有 **GitHub Actions** 需要长期 AK（用于推镜像和更新函数）。

## 四、OSS 上需要提前放好的文件

```
repostbot/
├── accounts.json          # 账号配置（从 config/accounts.example.json 改）
├── state.json             # 初始状态（从 config/state.example.json 改）
└── auth/firm_a.json       # 登录态（本机跑 recon.py 生成后上传）
```

**初始化 `state.json` 时注意**：必须给每家律所填 `last_published_at`（可从招聘列表页的「排序时间」列抄）。若留空，程序会认为从未发布而**立即触发一次置顶**，白白消耗一次 20 天机会。

### 用脚本初始化（推荐，避免手填出错）

```powershell
# 前置：.env 里填好 OSS_BUCKET / OSS_ENDPOINT / AccessKey
python tools/init_oss.py            # 交互式确认上次置顶时间
python tools/init_oss.py --yes      # 直接用默认值 2026-09-24 09:34
```

脚本会上传三件套（accounts.json / state.json / auth/<firm>.json）并**回读校验**，
同时打印推算出的下次可置顶日期供你核对。

## 五、登录态的处理（关键）

FC 上无人值守，登录态 Cookie 会过期。两条保障：

1. **自动登录兜底**（已实测通过）：登录态失效时，程序依次尝试
   `https://www.lawyers.org.cn/openid/login.jsp`（**生效的就是它**）与
   `https://oa.lawyers.org.cn/login.jsp`，用 `#j_username` / `#j_password` 填表提交。
   注意 OA 登录页的会话**不覆盖** recruitment 子域，所以 openid 登录页排在最前。
2. **失败即告警**：自动登录也失败时，返回失败并发管理员邮件，不会静默跳过

登录态文件仍是第一优先（更快、更不容易触发风控），本机生成后上传 OSS：

```powershell
python tools/recon.py --firm firm_a --browser msedge
# 登录后按 q 退出，登录态写入 .auth/firm_a.json，再上传到 OSS 的 repostbot/auth/firm_a.json
```

## 六、上线步骤

### GitHub Secrets 清单（6 个）

| Secret | 值 |
|---|---|
| `ALIYUN_ACCESS_KEY_ID` | RAM 子账号 AK（授权：ACR 推送 + FC 更新函数 + OSS 读写） |
| `ALIYUN_ACCESS_KEY_SECRET` | 同上 |
| `ACR_REGISTRY` | `registry.cn-shanghai.aliyuncs.com` |
| `ACR_NAMESPACE` | ACR 命名空间 |
| `FC_REGION` | `cn-shanghai` |
| `FC_FUNCTION_NAME` | 例：`repostbot` |

1. 创建 ACR 仓库 → 配置 GitHub Actions 的 6 个 Secrets
2. push 到 main → Actions 自动构建并推送镜像（首次可能 10~20 分钟）
3. FC 创建函数（容器镜像），填好环境变量与内存/超时
4. 先设 `DRY_RUN=true`，配定时触发器，**观察 2~3 天日志**
5. 确认 dry-run 日志中「距上次置顶 N 天」计算正确后，改 `DRY_RUN=false`
6. 满 20 天当天观察是否成功置顶、回执是否送达

## 八、本机定时运行（上云前的过渡方案 / 永久备份方案）

> 用途：确保**不错过置顶窗口**。首次真实置顶日是 2026-10-14，若届时 FC 尚未配好，
> 用本机计划任务兜底，避免再等 20 天。

### 1. 运行脚本

`scripts/run_daily.ps1`：切到仓库根目录 → 调用 `src/index.py` → 输出写入 `logs/daily_<时间戳>.log`，
同时用 `--trace` 记录网络请求到 `logs/trace_<时间戳>.json`。

行为由 `.env` 的 `DRY_RUN` 决定：`true` 只检查不真点，`false` 满 20 天当天真正置顶。

### 2. 注册计划任务（每天 09:00）

以**管理员或当前用户**身份在 PowerShell 执行：

```powershell
schtasks /create /tn "RepostBot" /sc daily /st 09:00 /f /tr "powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"D:\work\娜娜\自动招聘发布\scripts\run_daily.ps1\""
```

### 3. 常用管理命令

```powershell
schtasks /query /tn "RepostBot"        # 查看状态与下次运行时间
schtasks /run   /tn "RepostBot"        # 立即跑一次（用来验证配置）
schtasks /delete /tn "RepostBot" /f    # 删除任务
```

### 4. 注意事项

- **电脑需开机且已登录**（默认只在用户登录时运行）。若需要关机也能跑，必须上云（FC）。
- 任务计划程序中 PATH 可能不完整，脚本里对 python 路径做了兜底查找。
- 验证时先手动跑一次：`powershell -File scripts\run_daily.ps1`，再 `schtasks /run` 测试。
