## 〇之二、执行环境：云端（FC）为主，本机为副（2026-10-08 更新）

云端已打通（见 `docs/进度对账.md` §四之四），**10-14 的主执行路径是云端**：

| 动作 | 云端怎么做 |
|---|---|
| 触发 | 定时触发器每天 09:00（北京时间）自动跑，无需人工干预 |
| 演练 / 真跑切换 | 改 FC 环境变量 `DRY_RUN`（`true`→演练，`false`→到期真跑），保存即可 |
| 手动触发验证 | 函数 → 测试 → 「测试函数」（事件体留空即可） |
| 看结果 | SLS 日志（**须先启用**：函数 → 日志 → 一键启用）+ 回执邮件 |

### ⚠️ 云端的三个限制（`index.py` 的 FC 入口 `handler()`）

| 能力 | 云端可用性 | 说明 |
|---|---|---|
| `--doctor` | ❌ 不可用 | 仅 CLI 提供，云端只能提前在本机体检 |
| `--force`（跳过 20 天判断） | ❌ 不可用 | `handler()` 里 `force=False` 是硬编码的 |
| `--trace`（抓包） | ⚠️ 名义支持实际无用 | 只能用 `TRACE_PATH` 环境变量，但**容器文件系统随实例释放**，抓不到结果 |

⇒ **因此本清单里的「演练」与「抓包」两步（§二、§四）仍必须走本机 CLI**，
真正的置顶操作则由云端执行（或由本机 `--live` 执行，二选一，见下）。

### ⚠️ 防双跑：本机计划任务与云端触发器同为 09:00

两者都在 09:00 触发，若 10-14 当天两边都为 `DRY_RUN=false`，会同时点击 → 可能破坏防重复消耗保护。

**上线后必须二选一**：

- 推荐：**云端上线后停用本机计划任务**
  ```powershell
  schtasks /delete /tn "RepostBot" /f
  ```
  （本机兜底能力仍在，需要时改主分钟内恢复，见 `docs/部署手册.md` §八）
- 或保留本机，但确保本机 `.env` 的 `DRY_RUN=true`（只做核对，不真的点击）

### 万一失败

| 现象 | 处理 |
|---|---|
| `sort_time_after` 没变，判定 `failed` | **立即停止再跑**。站点可能已消耗机会但页面没体现。
| | 手动登录网站确认排序时间；已过保护窗口（`ACCEPT_RETRY_GUARD_DAYS=3`）才会再点 |
| `dialog.action` = `dismiss(unexpected)` | 弹的不是预期确认框，程序已自动取消，**没消耗机会**，先查明再说 |
| 登录失败 | `python tools/diag_login.py`，看 `logs/diag_*/` 里的截图 |
| 到 20 天之前误点了 | 服务端会返回 `-3` 拒绝（见页面结构 §6.3），先人工确认再决策 |

> 防重复消耗已内置：`state.accounts.firm_a.last_accept_at` 记录上次点击「确定」的时间，
> 3 天内不会二次点击。想强制再点请先清掉这个字段。
