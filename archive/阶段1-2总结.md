## 一、一句话结论

**整个项目的核心动作只有一个**：在招聘管理后台点一下「更新排序时间」，且**每 20 天只有一次机会**。
所有代码都是为了让这一个点击在正确的时间、以正确的方式自动发生。

## 二、阶段 1：勘察结论

### 2.1 页面链路（已实测打通）

```
https://oa.lawyers.org.cn/hall/                        OA 大厅（登录起点）
   ↓ 菜单「事务所招聘」
https://www.lawyers.org.cn/member/talentexchange       人才交流页
   ↓ 「点击此处发布招聘」→ /openid/login.jsp?loginSuccessUrl=...
https://recruitment.lawyers.org.cn/manager/index.jsp   ★ 招聘管理后台（真正操作页）
```

**代码里直接用最后这个地址**（`page_selectors.RECRUIT_MANAGER_URL`），有登录态时会直接进。
注意是 `manager` 不是 `manage`；未登录直接访问返回 **404**（不是跳登录页，这点很坑）。

### 2.2 置顶按钮

| 项 | 值 |
|---|---|
| 按钮文本 | **更新排序时间** |
| 选择器 | `button:has-text("更新排序时间")` |
| 是否需先选中行 | **否**（同组其他按钮未选行时都是禁用的，只有它可用） |
| 点击后 | 弹**浏览器原生 `confirm()`** |
| 弹窗原文 | 更新排序时间的操作在**20天之内只有使用一次**置顶的机会，请确认是否使用？ |

> ⚠ 这条弹窗文案是本项目最重要的业务规则：**20 天内只有一次机会，点了就消耗**。
> 所以不能"多点几次保险"，也不能失败就重试点击。

### 2.3 列表结构（Ext JS 2.x 老框架）

行：`div.x-grid3-row`；选中后加 class → `div.x-grid3-row-selected`
单元格：`td.x-grid3-td-0` ~ `td.x-grid3-td-9`

| # | 列名 | 常量 |
|---|---|---|
| 0 | 招聘标题 | `COL_TITLE` |
| 3 | 发布日期 | `COL_PUBLISH_DATE` |
| **6** | **排序时间**（计时依据） | `COL_SORT_TIME` |
| 9 | 状态（有效值「招聘中」） | `COL_STATUS` |

时间格式：`2026-09-24 09:34`。每页 20 条，**最新的一条在第 1 行**。

### 2.4 目标行判定逻辑（已实现在 `publisher.pick_target`）

```
状态列 == "招聘中" 的行 → 取排序时间最早的一条
若 (今天 - 排序时间).days >= 20 → 执行置顶
```

## 三、阶段 2：已实现的能力

### 3.1 代码地图（改代码看这里）

| 文件 | 职责 | 什么时候要改 |
|---|---|---|
| `src/page_selectors.py` | **所有选择器 + 业务常量** | **页面改版时只改这一个文件** |
| `src/publisher.py` | 核心流程：扫描列表 → 选行 → 判 20 天 → 点击 → 处理弹窗 → 复核 | 流程逻辑变化 |
| `src/config.py` | 环境变量、路径 | 新增配置项 |
| `src/index.py` | 命令行入口（默认 dry-run） | 新增命令行参数 |
| `tools/recon.py` | 勘察工具（页面改版时重新勘察用） | 需要重新抓页面结构 |
| `docs/页面结构.md` | 页面结构记录 | 勘察后同步更新 |
| `.auth/<firm>.json` | 各律所登录态（**已 gitignore**） | 失效时重跑 recon |

### 3.2 一次执行的完整流程

```
1. 用 storage_state 复用登录态（失效才走账号密码兜底）
2. goto 招聘管理后台；若落在登录页 → 报错并提示重跑 recon
3. 等 div.x-grid3-row 出现，扫描全部行
4. pick_target：状态=招聘中 且排序时间最早
5. 解析排序时间 → 算 days
6. days < 20 → skipped（除非 --force）
7. 点击该行（保证作用于正确岗位）→ 点「更新排序时间」
8. 弹窗处理：dry-run→取消；非 dry-run 且文案含「更新排序时间」→确定；否则取消
9. 非 dry-run 时 reload 复核排序时间是否变化 → 变了才算 success
10. 回写登录态
```

### 3.3 安全机制（不要削弱它们）

| 机制 | 说明 |
|---|---|
| 默认 dry-run | 不加 `--live` 绝不 `dialog.accept()` |
| 弹窗文案校验 | 弹的不是预期确认框 → 一律取消 |
| 成功判定 | 必须**复核排序时间确实变化**才算成功，避免"点了但没生效"被当成成功 |
| 无重试点击 | 因为 20 天只有一次机会，点击失败宁可下个周期再来 |

### 3.4 命令速查

```powershell
cd "d:\work\娜娜\自动招聘发布"

# 常规（dry-run + 20天判断）

```

## 四、踩过的坑（重要，别再踩）

| 坑 | 现象 | 解决 |
|---|---|---|
| 原生 `confirm()` 被静默取消 | 点了「更新排序时间」毫无反应 | 必须注册 `page.on("dialog")` |
| Playwright 自带 Chromium 打不开 OA | 页面卡住/打不开 | 加 `--browser msedge` 用本机 Edge |
| 新标签页不跟随 | 点了链接但导出的一直是旧页面 | `refresh_page()` 自动跟随最新标签页；也可用 `tabs` / `use <序号>` |
| 命令敲错窗口 | 在浏览器 F12 控制台输入命令报 JS 错 | 命令要敲在有 `命令>` 提示符的 PowerShell 窗口 |
| 直接访问 `manage/` 404 | 未登录时该路径返回 404 | 先登录，或直接用 `manager/index.jsp` |
| ExtJS 按钮 id 会变 | `ext-gen18` 等每次加载不同 | 一律用 `button:has-text("...")` 文本定位 |
| Python 标准库冲突 | 自定义 `selectors.py` 会 shadow 标准库 | 改名为 `page_selectors.py` |
| Windows GBK 控制台 | 打印 emoji 抛 `UnicodeEncodeError` | 代码里不要用 emoji |
| Cron `*/20` 不是每 20 天 | 表示每月 1 日和 21 日，周期退化成 30 天 | 每天触发 + 程序自己判 20 天 |
| `passport.lawyers.org.cn` 不通 | 连接失败 | 登录入口以 OA 为准 |

## 五、当前限制与待办

### 已知限制

1. **真实置顶未实测**——要等满 20 天（2026-10-14 之后）
